## 1. Problem Statement

1.1 shows lifting only as a mixed pile, one boulder per rep, sized by the weight of each lift. Some lifters want the story told differently: one massive boulder they carry for the whole session or their whole lifting career, or their total weight expressed in a single tier ("1,530 Pebbles", "25 Monoliths"). Without a way to switch, the display feels fixed and one view cannot suit both the bragging-rights and small-progress mindsets. Letting users choose how their weight is shown makes the app more personal and gives each session more replay value.

## 2. Goals

- Let the user pick a **scope**: this session or lifetime (1.1's 7-day scope stays available).
- Let the user pick a **display mode**: Mixed pile (1.1 default), One big boulder, or All one tier (all Pebbles, Stones, Rocks, Boulders, Great Boulders or Monoliths).
- Remember the choice between visits, on-device.
- Keep the exact total weight identical in every mode.
- Reuse 1.1's tier table and total-weight calculation rather than duplicating logic.

## 3. Non-Goals

- New tiers or changes to tier bounds (owned by 1.1).
- Animated carrying scenes or 3D rendering (see Open Question 3).
- Comparing against other users, or sharing (1.3).
- Per-exercise or per-muscle-group breakdowns.
- Accounts or cloud sync.

## 4. Personas & User Stories

- **As a lifter**, I want to see my session as one massive boulder so that the whole workout feels like a single big achievement.
- **As a long-time lifter**, I want to see my lifetime total as one boulder so that years of work feel monumental.
- **As a beginner**, I want to see my total in Pebbles so that small totals still produce satisfying, countable numbers.
- **As an advanced lifter**, I want my total in Great Boulders or Monoliths so that I am not looking at thousands of tiny icons.
- **As any user**, I want the app to remember my choice so that I do not reselect it every visit.
- **As a screen reader user**, I want each mode to read out clearly so that I get the same information as sighted users.

## 5. Functional Requirements

- **FR-1.** The system MUST provide a scope control with at least Session and Lifetime (and keep 1.1's 7-day scope).
- **FR-2.** The system MUST provide a display mode control with three modes: Mixed pile, One big boulder, and All one tier.
- **FR-3.** In All one tier mode the system MUST let the user choose any tier from the 1.1 table (Pebble, Stone, Rock, Boulder, Great Boulder, Monolith).
- **FR-4.** In All one tier mode the system MUST express the total weight in units of the chosen tier's **reference weight**: `whole = floor(totalLb / refLb)` and `fraction = (totalLb mod refLb) / refLb`, and show both (for example "153 Rocks + 0.06 of a Rock").
- **FR-5.** In One big boulder mode the system MUST render a single boulder labelled with the exact total in the user's unit, sized by cube-root scaling (see Section 10) so that visual volume tracks weight.
- **FR-6.** The system MUST show the exact total weight (lb or kg) in every mode.
- **FR-7.** The system MUST persist scope, display mode and chosen tier in local settings and restore them on load.
- **FR-8.** The system MUST default to Session scope and Mixed pile on first launch, so 1.1 behaviour is unchanged for existing users.
- **FR-9.** The system MUST cap drawn icons per view (for example 20 per tier row, matching 1.1 FR-9) and collapse the rest into a "x N" label.
- **FR-10.** The system MUST provide a text equivalent of the current view for every mode.
- **FR-11.** The system MUST label All one tier and One big boulder views as "weight expressed in" or "weight of", so users understand these are total weight, not the rep count shown in Mixed pile.
- **FR-12.** The system SHOULD show a partial boulder (fill or clipped icon) for the fractional remainder in All one tier mode.
- **FR-13.** The system SHOULD show a small reference strip (Pebble to Monolith) beside the big boulder so the size has context.
- **FR-14.** The system MAY show a one-line hint when the chosen tier is a poor fit (for example "0 Monoliths yet, you are 16 percent of the way").

### Reference weights (used only by All one tier and One big boulder)

1.1's tiers are ranges (a Pebble is any lift under 10 lb), so a single "one Pebble weighs X" value is needed to turn total weight into units. Proposed rule: each tier's reference weight is its lower bound, except Pebble, which has none and uses 5 lb.

| Tier | Range (1.1) | Reference weight (lb) |
|---|---|---|
| Pebble | under 10 | 5 (proposed) |
| Stone | 10 to under 50 | 10 |
| Rock | 50 to under 100 | 50 |
| Boulder | 100 to under 200 | 100 |
| Great Boulder | 200 to under 300 | 200 |
| Monolith | 300 and up | 300 |

### Worked examples (checked against the tables)

For the AC-1 workout from 1.1 (total 7,653 lb, 105 reps): Mixed pile is 15 Great Boulders, 24 Boulders, 30 Stones and 36 Pebbles.

| Total | All Pebbles | All Stones | All Rocks | All Boulders | All Great Boulders | All Monoliths |
|---|---|---|---|---|---|---|
| 7,653 lb | 1,530 + 0.6 | 765 + 0.3 | 153 + 0.06 | 76 + 0.53 | 38 + 0.265 | 25 + 0.51 |
| 49 lb | 9 + 0.8 | 4 + 0.9 | 0 + 0.98 | 0 + 0.49 | 0 + 0.245 | 0 + 0.163 |
| 1,000,000 lb | 200,000 | 100,000 | 20,000 | 10,000 | 5,000 | 3,333 + 0.333 |

One big boulder for 7,653 lb is drawn about 11.5 times the width of a reference Pebble (cube root of 7,653 / 5).

## 6. Non-Functional Requirements

- **Performance** — switching mode or scope re-renders in under 100 ms; totals reuse 1.1's cached all-time figure.
- **Security** — no network calls; settings contain no sensitive data.
- **Privacy & Compliance** — local-only; no PII.
- **Accessibility** — WCAG 2.1 AA: controls are a labelled radio or tab group operable by keyboard; the text summary is primary; the big boulder has an accessible name including the exact weight; motion respects `prefers-reduced-motion`.
- **Scalability** — icon counts are capped, so 200,000 Pebbles renders as at most the cap plus a label.
- **Reliability** — invalid or stale saved settings (for example a removed tier id) fall back to defaults instead of crashing.
- **Observability** — dev-only logging of mode changes; no telemetry.
- **Maintainability** — one `DisplayMode` union type and one renderer per mode; no mode-specific maths outside `src/lib/`.
- **Internationalization** — mode names, labels and fractions externalised; decimals follow locale.
- **Backward compatibility** — no data changes; a missing settings field means defaults.

## 7. Acceptance Criteria

- **AC-1.** *Given* a fresh install *When* the Boulders page opens *Then* Session scope and Mixed pile are selected (1.1 behaviour).
- **AC-2.** *Given* 7,653 lb this session *When* the user selects All one tier, Pebble *Then* the view shows 1,530 Pebbles plus 0.6 of a Pebble and the exact total of 7,653 lb.
- **AC-3.** *Given* 7,653 lb *When* the user selects All one tier, Rock *Then* the view shows 153 Rocks plus 0.06 of a Rock.
- **AC-4.** *Given* 49 lb *When* the user selects All one tier, Monolith *Then* the view shows 0 Monoliths and about 16 percent progress, not an error or blank.
- **AC-5.** *Given* 1,000,000 lb lifetime *When* All Pebbles is selected *Then* at most the icon cap is drawn plus a "x 200,000" label.
- **AC-6.** *Given* lifetime scope and One big boulder mode *When* the user switches to Session *Then* the boulder resizes to the session total and the label shows the session total.
- **AC-7.** *Given* the user picked a mode and reloads the page *When* the app opens *Then* the same scope, mode and tier are restored.
- **AC-8.** *Given* saved settings referencing a tier that no longer exists *When* the app loads *Then* it falls back to Mixed pile with no error.
- **AC-9.** *Given* zero lifted weight *When* any mode is chosen *Then* the empty state from 1.1 is shown and no mode shows NaN or negative values.
- **AC-10.** *Given* a keyboard-only user *When* they tab through the controls *Then* every scope, mode and tier option is reachable and announced with its selected state.
- **AC-11.** *Given* the same data *When* the user cycles through all modes *Then* the displayed exact total weight never changes.
- **AC-12.** *Given* All one tier or One big boulder mode *When* the view is shown *Then* it is labelled as total weight, not a rep count (FR-11).

## 8. Data Model

Local-only, so no SQL migrations. Extends the 1.1 `settings` store.

- `settings.scope`: `session` | `week` | `lifetime` (default `session`).
- `settings.displayMode`: `mixed` | `single-boulder` | `single-tier` (default `mixed`).
- `settings.singleTierId`: a tier id from `tiers.ts` (default `pebble`; only read when mode is `single-tier`).
- Tier config gains `refLb` per tier (5, 10, 50, 100, 200, 300).
- No new stores. Results are derived at read time, as in 1.1.
- Backfill: none. Missing fields use defaults.

## 9. API Surface

No HTTP routes. Internal contract added to `src/lib/boulders.ts`:

```ts
type DisplayMode = "mixed" | "single-boulder" | "single-tier";

type SingleTierResult = {
  tierId: string;
  whole: number;      // floor(totalLb / refLb)
  fraction: number;   // 0 <= fraction < 1
  totalLb: number;
};

type SingleBoulderResult = {
  totalLb: number;
  scaleVsPebble: number; // cbrt(totalLb / pebbleRefLb), for rendering only
};

function toSingleTier(totalGrams: number, tier: Tier): SingleTierResult;
function toSingleBoulder(totalGrams: number, tiers: Tier[]): SingleBoulderResult;
```

If accounts are added later, mirror these under `GET /api/v1/me/boulders?scope=&mode=&tier=` with OpenAPI docs.

## 10. UI / UX

- **Modified page:** Boulders (from 1.1) gains a controls bar above the graphic.
- **New components:** `ScopeToggle`, `ModeToggle`, `TierPicker` (visible only in single-tier mode), `SingleBoulder`, `TierRow`, `ReferenceStrip`.
- **Key flows:**
  1. User opens Boulders and sees the default Session / Mixed pile.
  2. User taps Lifetime, and the view updates to the lifetime data.
  3. User chooses One big boulder, and a single boulder appears with the exact weight label and reference strip.
  4. User chooses All one tier, picks Stones, and sees a Stone count with a partial Stone.
  5. User leaves and returns, and the same choices are restored.
- **Big boulder sizing:** diameter = reference Pebble diameter x cbrt(totalLb / 5), clamped to the viewport; when clamped, show the true ratio in text ("about 11.5 times a Pebble").
- **States:** empty (no sets), loading (skeleton), error (storage unavailable), offline (no change), extreme-total (clamped size and "x N" labels).
- **Responsive:** controls collapse into a select or segmented control on narrow screens; the graphic scales to width.
- **Accessibility:** controls in a `role="radiogroup"` or tab set with visible focus; `aria-live="polite"` announces the new summary on change; the graphic has `role="img"` with an accessible name.
- **i18n keys:** `scope.session`, `scope.week`, `scope.lifetime`, `mode.mixed`, `mode.singleBoulder`, `mode.singleTier`, `singleTier.summary`, `singleTier.fraction`, `singleBoulder.summary`, `singleBoulder.scale`.

## 14. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Mixed pile counts reps (105 boulders) while All one tier counts weight (25 Monoliths), so numbers look contradictory | H | H | Label each view clearly (FR-11, AC-12); show the exact total in every mode; add a "how this is counted" tooltip |
| All Pebbles at high totals draws thousands of icons and slows the page | H | M | Icon cap and "x N" label (FR-9); test with 200,000 Pebbles |
| Reference weights are a new rule not in the request (Pebble = 5 lb, others = lower bound) | H | M | Keep in config; confirm in Open Question 1 |
| Big boulder size is misleading (cube-root scaling looks small) | M | M | Always show the exact total and a reference strip; show the true ratio in text |
| Too many controls (scope x mode x tier) overwhelms new users | M | M | Sensible defaults; hide the tier picker unless single-tier mode is on |
| Saved settings become invalid after tier changes | L | M | Validate on load and fall back to defaults (AC-8) |
| Refactoring 1.1's pile into modes breaks 1.1 tests | M | M | Keep 1.1's tests unchanged and green before adding modes |

## 15. Rollout Plan

- **Feature flag:** `boulder_display_modes`, default OFF; when off, only the 1.1 Mixed pile and its scopes show.
- **Sequencing:** extend settings and pure functions with tests, then the renderers, then the controls, then flip the flag.
- **Dogfood:** you and a few friends try every mode on a real week of workouts and note which one they keep.
- **GA criteria:** all ACs pass, axe has no serious violations, the 200,000 Pebble case stays under the performance target.
- **Rollback:** turn the flag off; settings fields are ignored and the 1.1 view returns, with no data to reverse.

## 16. Test Plan

- **Unit** — `toSingleTier` at boundaries (0, 49, 7,653, 1,000,000 lb), fraction always in [0, 1), `toSingleBoulder` scale values (5 lb is 1.0, 7,653 lb is about 11.5), settings fallback on invalid ids.
- **Integration** — settings persist and restore across reloads; scope change recomputes from IndexedDB; lifetime uses the cached total.
- **End-to-end** — Playwright: cycle every scope and mode, pick each tier, reload and check persistence, check the exact total never changes (AC-11).
- **Security** — confirm no network requests; check that settings read from storage cannot inject markup.
- **Accessibility** — axe automation, plus manual keyboard and screen-reader pass on the controls and live-region announcements.
- **Performance / load** — 200,000 Pebbles and lifetime data of 100,000+ sets; switching mode under 100 ms.
- **Manual exploratory** — tiny totals, huge totals, unit toggle while in each mode, very narrow screens, reduced-motion setting.

## 18. Open Questions

1. **Reference weights:** what should one Pebble weigh in All one tier mode? The plan uses 5 lb (Pebble has no lower bound) and each other tier's lower bound. Is that intended, or should All one tier instead re-count reps at the chosen tier?
2. **Do the modes have to agree?** Mixed pile counts reps; All one tier counts weight. Is showing both acceptable with clear labels, or should every mode count the same thing?
3. **Does "carry" need a visual?** You described a massive boulder "they carry". Should there be a figure or silhouette carrying it, or is a single large boulder enough for MVP?
4. **Is cube-root scaling the right size rule?** It keeps volume proportional to weight, but 7,653 lb is only about 11.5 times as wide as a Pebble.
5. **Scope list:** keep the 7-day scope alongside Session and Lifetime, or drop it to simplify?
6. **Per-scope memory:** one saved mode for everything, or a separate mode for Session and for Lifetime?
7. **Feature IDs:** does history (charts over time) become its own later feature?
